# inline-override-docを実装する

packages/compiler/src/core/parser.ts

にパーサーの実装がある
この時点では普通にコメントがパースされる

👺 > comment /**
       * 🍋
       */ { kind: 50, pos: 321, end: 346 }

ただし、モデルに紐づいているかどうかはその記述次第で、
静的に宣言されたモデルであればdocCommentがModelStatementのノード（docs）に紐づいている

parseAnnotationsでdocCommentとしてパースするかどうか、parseDocListの
` mutate(range.comment).parsedAsDocs = true;`が実行される必要があるが、
現状Operation statementではこの操作が実行されないため、ノード（docs）と紐づいていない

```tsp
op foo(): /** One-liner */
{ bar: string };
```
のような構文を解析する際、まずは`:`直後のBlockCommentをパースしてdocsに紐付ける

skipParsingDocNodesとinvalidAnnotationTargetについて
例えばOperationの引数が複数である場合などがparseListの対象となるとき、
特定のExpressionなどはdocCommentをdocsとしてパースしないようにする必要がある

```ts
  const ExpresionsBase = {
    allowEmpty: true,
    delimiter: Token.Comma,
    toleratedDelimiter: Token.Semicolon,
    toleratedDelimiterIsValid: false,
    invalidAnnotationTarget: "expression",
    allowedStatementKeyword: Token.None,
  } as const;
```

このような定義をする場合、現状はこうなる。

```tsp
import "@typespec/http";
using Http;
/** This is Second */
model Second { baz: string };
union MyResponse {
 /** First-union */
 { @statusCode code: 201; bar: string };
 /** Second-union */
 Second;
};
op foo():
/** Override Response union */
MyResponse |
/** Override third-union */
{ @statusCode code: 408; qux: string };
```

```yaml
openapi: 3.0.0
info:
  title: (title)
  version: 0.0.0

            - bar

      type: object

          type: string

```
